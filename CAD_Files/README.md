## Files

### `oil-filter-thread-adapter.py`

FreeCAD Python macro that generates a 3-D solid of a billet thread adapter
for the Duramax 3.0 LM2 / LZ0 engine.

| Feature | Spec |
| ------- | ---- |
| Block-side thread | 1"-16 UNF male (screws into engine) |
| Sandwich-plate thread | 13/16"-16 UNF male (sandwich plate mounts here) |
| Hex collar | 1-1/2" AF |
| Through-bore | 0.500" dia (oil passage) |
| O-ring groove | Viton -112 on hex seating face |
| Chamfers | 45° at both thread entries |
| Material (spec) | 6061-T6 billet aluminum |
| Thread standard | ASME B1.1 Class 2A external |

Configurable constants at the top of the file control all dimensions.
Set `BLOCK_THREAD_TYPE = "FEMALE"` if your block has a male stud instead
of a female boss.

### `setup-freecad-env.sh`

Shell script that prepares the Python environment. See [Environment Setup](#environment-setup).

### `run-macro.sh`

Auto-generated by `setup-freecad-env.sh`. Selects the correct Python
interpreter (FreeCADCmd → venv → system python3) and runs the specified macro.

## Environment Setup

### Quick Start

```bash
cd CAD_Files
chmod +x setup-freecad-env.sh
./setup-freecad-env.sh
```

That is all that is needed. The script will guide you through any missing
dependencies.

### Requirements

| Requirement | Version | Notes |
| ----------- | ------- | ----- |
| Python | 3.10+ | system or Homebrew |
| FreeCAD | 0.21+ | see below |
| bash | 3.2+ | macOS default is sufficient |

Python is used to install the supporting venv. FreeCAD provides its own
bundled Python interpreter for running the macros — its version does not
need to match the system Python.

### FreeCAD Installation

FreeCAD MUST be installed separately. It is not pip-installable in a way
that provides the full geometry kernel.

| Platform | Download |
| -------- | -------- |
| macOS (app bundle) | [freecad.org/downloads.php](https://www.freecad.org/downloads.php) |
| Ubuntu / Debian | `sudo apt install freecad` or AppImage from the download page |
| Arch Linux | `sudo pacman -S freecad` |
| conda (cross-platform) | `conda install -c conda-forge freecad` |

The setup script searches the following paths automatically:

```text
/Applications/FreeCAD.app/Contents/MacOS/FreeCADCmd   (macOS)
/usr/bin/freecadcmd                                    (Linux apt)
/usr/local/bin/freecadcmd                              (Linux custom install)
/snap/bin/freecad                                      (Linux snap)
```

### What the Script Does

1. Locates Python 3.10+ on the system.
2. Creates a `.venv` virtual environment in this directory.
3. Installs supporting packages via pip:
   - `numpy` — numerical and thread geometry calculations
   - `scipy` — engineering math (clearances, fits)
   - `matplotlib` — optional: plotting temperature matrices
4. Detects the FreeCAD installation and injects its library path into the
   venv via a `.pth` file so that `import FreeCAD` works inside the venv.
5. Generates `run-macro.sh`.

> **Note:** The `.pth` injection (step 4) works when FreeCAD and the venv
> use the same Python ABI version. If they differ, `import FreeCAD` will
> still fail inside the venv, but `run-macro.sh` will fall back to using
> `FreeCADCmd` directly, which always works.

## Running Macros

### FreeCAD GUI (recommended for first run)

1. Open FreeCAD.
2. `Macro` ▸ `Macros…`
3. Browse to the `.py` file in this directory.
4. Click **Execute**.

The macro creates a new document, builds the 3-D solid, optionally opens a
TechDraw drawing page, and prints a dimension summary to the Report View
(`View` ▸ `Panels` ▸ `Report View`).

### Command Line via FreeCADCmd

```bash
# macOS
/Applications/FreeCAD.app/Contents/MacOS/FreeCADCmd \
    oil-filter-thread-adapter.py

# Linux
freecadcmd oil-filter-thread-adapter.py
```

`FreeCADCmd` runs headless. The document is created in memory; you MUST
save it manually to a `.FCStd` file, or add a save call to the script:

```python
doc.saveAs("/path/to/Output.FCStd")
```

### run-macro.sh Wrapper

After running `setup-freecad-env.sh`, a `run-macro.sh` wrapper is generated
that selects the correct interpreter automatically:

```bash
./run-macro.sh oil-filter-thread-adapter.py
```

The wrapper priority order:

1. `FreeCADCmd` — FreeCAD's own Python (most compatible, always preferred)
2. `.venv/bin/python` — venv with FreeCAD path injected
3. `python3` — system fallback (FreeCAD modules will be missing)

## Script Reference

### `oil-filter-thread-adapter.py` — configuration variables

All user-editable constants are in the **Specification** section near the
top of the file. Do not edit below the `# Thread calculations` comment.

| Variable | Default | Description |
| -------- | ------- | ----------- |
| `BLOCK_MAJOR_IN` | `1.0000` | Block-side thread major diameter (inches) |
| `BLOCK_TPI` | `16` | Block-side threads per inch |
| `BLOCK_LEN_IN` | `0.625` | Block-side engaged thread length (inches) |
| `BLOCK_THREAD_TYPE` | `"MALE"` | `"MALE"` = external stud; `"FEMALE"` = internal bore |
| `SAND_MAJOR_IN` | `0.8125` | Sandwich-plate thread major diameter (13/16") |
| `SAND_TPI` | `16` | Sandwich-plate threads per inch |
| `SAND_LEN_IN` | `0.625` | Sandwich-plate engaged thread length (inches) |
| `HEX_AF_IN` | `1.500` | Hex collar across-flats (inches) |
| `HEX_HEIGHT_IN` | `0.375` | Hex collar height (inches) |
| `BORE_DIA_IN` | `0.500` | Through-bore diameter (oil passage, inches) |
| `ORING_ID_IN` | `1.075` | O-ring groove inner diameter (inches) |
| `ORING_WIDTH_IN` | `0.118` | O-ring groove width (inches) |
| `ORING_DEPTH_IN` | `0.082` | O-ring groove depth (inches) |
| `CHAMFER_DEG` | `45.0` | Lead chamfer angle (degrees) |

### Thread calculation functions

| Function | Description |
| -------- | ----------- |
| `unf_minor_ext(major, tpi)` | ASME B1.1 external thread minor diameter |
| `unf_minor_int(major, tpi)` | ASME B1.1 internal thread minor diameter |
| `unf_pitch_dia(major, tpi)` | ASME B1.1 pitch diameter |

## Output Files

After running the macro, export files from the FreeCAD Part workbench:

```text
Part menu ▸ Export…   →  select format (.step / .dxf / .stl)
```

Exported files SHOULD be named per the project naming convention:
`Oil-Filter-Thread-Adapter-V<n>.<ext>` (e.g. `Oil-Filter-Thread-Adapter-V1.step`).

STEP files are preferred for sharing with machinists. DXF with a toleranced
PDF drawing is required before sending to a machine shop.

## Naming Conventions

Files in this directory follow the project-wide conventions in
[`../CONTRIBUTING.md`](../CONTRIBUTING.md):

- **Code and script files:** All lowercase words, `-` as demarcator, lowercase extension.
  Example: `oil-filter-thread-adapter.py`, `setup-freecad-env.sh`
- **Markdown files:** All UPPERCASE words, `-` as demarcator, lowercase `.md` extension.
  Example: `README.md`, `CONTRIBUTING.md`
- **Design and drawing files:** CamelCase words, `-` as demarcator, lowercase extension.
  Example: `Oil-Filter-Thread-Adapter-V1.step`, `LM2-Filter-Boss-Drawing.pdf`
- **Acronyms:** Industry-standard capitalization — `CAD`, `DXF`, `STEP`, `UNF`, `AN`.
- **Versions:** Capital `V` followed by integer — `V1`, `V2`.
- **Generated files** (`.venv/`, `run-macro.sh`) are gitignored or listed
  as generated in `.gitignore`.
